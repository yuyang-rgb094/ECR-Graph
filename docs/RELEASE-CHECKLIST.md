# 公开发布前检查清单

工具包在私有工作区中开发。公开前必须逐项完成以下检查，并由项目 Owner 签字确认。

## 1. 内容边界

- [ ] 仓库中没有任何真实企业的 ECR、受控文件、派生文本、图谱产物或审查报告。
- [ ] 示例数据全部来自 `ecr_graph/_synthetic.py`，均为虚构，并已标注“虚构”。
- [ ] 规则包和画像中没有真实企业的文件编号前缀、型号名、人员姓名或部门名。
- [ ] 文档中没有真实项目名称、客户名称、内部票据号或工作区路径。
- [ ] 测试和示例的输出目录（`work/`）没有提交进仓库。

## 2. 自动扫描

在仓库**之外**维护一份私有禁用词表，内容包括公司名、产品名、编号前缀、人员姓名和内部系统名，每行一个词，或写成 `re:<正则>` 形式：

```bash
python3 -m ecr_graph leakscan . --denylist /private/path/denylist.txt
```

- [ ] 扫描结果为 0 处命中。如有确需保留的通用模式，逐条写明理由。
- [ ] 新建一个干净的仓库，只复制已审查的文件。不要沿用任何包含历史内容的 Git 记录。
- [ ] 发布前用 `git log -p` 检查**完整历史**。

## 3. Markdown 头信息

工作区治理要求的 frontmatter 字段（`title`、`status` 等）可以保留，GitHub 会把它们渲染成表格；也可以在发布副本中去掉。

- [ ] 发布副本中没有工作区内部的 ID 前缀或受众角色代号。

## 4. 许可证与依赖

- [ ] 选定许可证，候选为 Apache-2.0 或 MIT，由 Owner 决定。
- [ ] 运行时没有第三方依赖。可选组件的许可证在 README 中注明：MinerU 为 MinerU Open Source License（基于 Apache 2.0 并附加条件），LibreOffice 为 MPL-2.0，pypdf 为 BSD。
- [ ] MinerU 的额度、限制和 API 说明已按发布当天的官网内容重新核对。

## 5. 表述

- [ ] README 和规则包写明：所有输出均为候选，不构成合规或注册结论。
- [ ] 注册影响规则包标注为示例，不代表任何监管机构的规则。
